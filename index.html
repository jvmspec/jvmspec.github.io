The feedback loop

A useful failure.
Then one honest step.

JavaSpec keeps framework mechanics separate from domain judgment. It can discover what is structurally missing and prepare boring scaffolding; only you decide what the behavior means.

J/S feedback
signal

Capability map

Small core.
Deliberate extensions.

The dependency-free core carries the everyday specification workflow. Optional adapters add build-tool, platform, and instrumentation integrations without changing that boundary.

CORE / 010 runtime deps
{}

Write behavior, not ceremony

Subject-centric it_* examples, typed proxy expectations, lifecycle hooks, matchers, Prophecy-style collaborators, and explicit pending/skip semantics.

  • ObjectBehavior<T>
  • method().shouldReturn(value)
  • Java 8 source compatibility
CORE / 02source-aware

Generate the boring parts

Describe specs, inspect missing production structure, preview a plan, and explicitly authorize generation or update work.

  • Spec + support scaffolds
  • Constructor and method skeletons
  • Atomic, guarded source writes
CORE / 03portable
▶

Run wherever Java runs

Use the CLI directly, embed the no-exit launcher, or connect the same specifications to your preferred build and test platform.

  • Pretty, progress, JSON formatters
  • JSON and JUnit XML reports
  • Stable IDs and source locations
OPTIONAL / 04isolated adapters

Reach past interfaces—only when the design calls for it.

Core doubles stay intentionally conservative. Separate ByteBuddy-based artifacts support concrete subclasses and instrumentation-aware final, static, and construction scopes.

javaspec-bytecode-doublesconcrete and abstract class doubles
javaspec-bytecode-agentfinal classes, static methods, construction
